# 发版更新日志

## 目标

维护根目录的 `CHANGELOG.md`，让应用内“更新日志”始终展示清楚、简短、用户能读懂的功能变化。

## 步骤

1. 读取 `package.json` 和 `CHANGELOG.md`，确认当前版本号与已有的最新版本。
2. 确认本次发版版本号；如果用户没有指定，先询问，不要自行猜测。
3. 在 `CHANGELOG.md` 的 `# 更新日志` 下方新增版本段，最新版本放在最上面：

   ```markdown
   ## v0.3.0 · 2026-11-17

   ### 新增
   - 增加了快捷键，可以快速创建待办子项。

   ### 优化
   - 任务操作改为快捷按钮和右键菜单，常用操作更容易找到。
   ```

4. 版本段的日期使用 `YYYY-MM-DD`。按“新增 / 优化 / 修复”分组，没有内容的分组省略。
5. 每条只写一句用户能感知的变化，例如“增加了快捷键快速创建 todo 项”。不要写文件名、函数名、数据库字段、测试步骤或大段技术细节。
6. 合并同类项，每个分组建议不超过 5 条；跨版本保留历史内容，不改写旧版本。
7. 如果本次同时发版，把 `package.json` 的 `version` 改为同一版本号，并同步 README、任务清单和安装包版本引用。
8. 运行 `npm run typecheck` 和 `npm run build`；需要安装包时运行 `npm run dist`。

## 排版要求

- 版本标题固定为 `## vX.Y.Z · YYYY-MM-DD`，应用内会按这个格式解析。
- 分组标题固定为 `### 标题`，条目使用 `- `。
- 版本与版本之间空一行，便于阅读。
- 面向普通用户描述“能做什么”，而不是“代码怎么改”。

## 不要做

- 不要逐个罗列 commit。
- 不要写内部重构、依赖升级或测试细节，除非用户明确要求。
- 不要删除或改写历史版本的更新内容。
